OpenMAIC 代码地图与包依赖

发表于2026-11-11|更新于2026-11-11|AI辅助开发智能体应用
|浏览量:
项目/OpenMAIC/核心知识
OpenMAIC模块参考进阶

结论：这是一个 Next.js 16 App Router 单体 + pnpm workspace 多包的混合体。
dsl 是零依赖基石，其余包单向依赖它；根应用用 workspace:* 消费全部包，但包之间不反向依赖根。
改动 packages/*/src 后必须重建 dist，否则根目录的 tsc / 单测会报一堆假错误。

顶层目录职责

目录 职责 常见误判
app/ 页面 + 全部 API 路由（约 110 个 route.ts） 不是「只有页面」，API 全在这里
components/ React UI：ai-elements/、chat/、edit/、slide-renderer/、stage/ 导出菜单在 components/stage/header-controls.tsx，不在 lib/export/
lib/ 应用逻辑，约 55 个子目录：server/、store/、export/、video-export-app/、device-storage/、media/、pbl/ 最大的一坨，先按子目录定位
packages/ 可发布 SDK 包 + vendor（@openmaic/*、mathml2omml、pptxgenjs、docs） packages/docs/ 是 Fumadocs 站点脚手架，不是产品文档
configs/ 编辑器静态常量（animation/chart/element/font/hotkey/…） 纯前端配置，不是部署配置；部署配置在 openmaic.yml + .env
e2e/ Playwright 用例、Page Object、fixtures 与 eval/ 不是一回事
eval/ 离线评测 runner / judge / reporter + scenarios JSON 不走 vitest 常规用例路径
skills/ Agent 工作台用的 SKILL.md 与 references 不是 npm 包
render-service/ 独立 MP4 渲染服务（自己的 package.json、vitest 配置） 不在 Next 构建里，由 compose 单独起
deploy/ 进 git 的私有部署清单与 sidecar 镜像 与 .workbuddy/ 分工，见 [[08-deployment-topology-and-config-layering]]
.workbuddy/ 本机私有资料，被 .git/info/exclude 忽略 上游 git 看不到整个目录

七个 SDK 包与依赖方向

包 职责 关键导出 / 入口
@openmaic/dsl 类型、JSON Schema、validator、migration、normalize dsl/src/index.ts；子路径 ./schema/*
@openmaic/geometry → dsl SVG path 校验、几何变化判定 validateSvgPath、INPUT_PATH_LIMITS / RENDER_PATH_LIMITS
@openmaic/renderer → dsl+geometry PPTist 风格 Slide JSON 渲染 SlideCanvas、SlideElement、SlideRendererProvider；子路径 ./elements/./snapshot/./fonts.css
@openmaic/editor → dsl+renderer+geometry 可组合编辑核心 子路径 /core、/react、/ui
@openmaic/storage → dsl 可插拔持久化（Browser / Http / Pg 三套实现） BrowserKVStore/HttpKVStore、BrowserDocumentStore/PgDocumentStore、PgAssetStore、AssetCollector
@openmaic/generation → dsl+geometry 纯生成契约 + prompt 资产（templates/snippets/prompts-pbl） index.ts，子路径 ./browser
@openmaic/importer → dsl pptx → Slide JSON parse()、importPptx、parsedToSlides、normalizeImportedSlides

@openmaic/storage/src/index.ts 里 asset/references.js 故意不 re-export：防止在事务外调用破坏
资产引用计数表。这是「导出清单看起来少了一个模块」的原因，不是遗漏。

构建顺序（package.json:11）

postinstall 自动跑 build:packages；pnpm dev / pnpm build 还会额外跑
build-standalone-player.mjs 与 sync-interactive-assets.mjs。
环境契约：Node >=22.19.0、pnpm 10.28.0、Next 16.3.3、React 19.2.3。

三条实操约束

  1. **改 packages/*/src 后先 pnpm build:packages**，否则根 tsc / vitest 读的是旧 dist。
  2. public/ 只能挂子路径，不能整目录挂进容器：会盖掉构建期生成的 standalone-player，
    离线单文件导出随即 404（见 [[08-deployment-topology-and-config-layering]]）。
  3. configs/ 与 openmaic.yml 是两回事：前者是前端常量，后者才是 provider/slot 部署配置。

来源与可信度

package.json（脚本、依赖、engines、版本）、各包 package.json 与 src/index.ts、
packages/@openmaic/storage/src/index.ts:72-77（故意不 re-export 的注释）。均为源码静态核对，未运行构建。
包依赖关系见 dsl/src/index.ts 与各包 import 图。
