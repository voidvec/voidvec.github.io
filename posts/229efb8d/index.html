OpenMAIC 部署拓扑与配置分层

发表于2026-11-12|更新于2026-11-12|云原生运维容器化
|浏览量:
项目/OpenMAIC/核心知识
OpenMAIC数据与运维进阶

结论：整套栈由根目录三个 compose 文件自动叠加（不要用 -f 指定），
配置按「构建期 / 运行期 / 应用启动时」三个时点生效，混淆这三者是绝大多数「改了没生效」的根因。

1. 服务与 profile

服务 来源 作用
openmaic 主 Next.js 应用
postgres 主 主栈不发布端口
render-service 主，profiles: [video-export] MP4 渲染，仅 expose: 9000 内网
piper-tts override，profiles: [tts-fallback] 离线 TTS，8090
edge-tts override，常驻 OpenAI 兼容 TTS shim，8091
deliver-sidecar override，常驻 阿里云盘 CLI + 飞书通知，8099

只有两个 profile：video-export、tts-fallback。网络：default + render(internal:true)。

启动（仓库根）：docker compose --profile video-export up -d → 127.0.0.1:3100。
本地开发库：pnpm db:up（-p openmaic-dev-db -f docker-compose.db.yml，发布 5432 到回环）。

2. 端口与挂载

  • 主文件：'${OPENMAIC_PUBLISH_ADDRESS:-127.0.0.1}:${OPENMAIC_PORT:-3000}:3000'；
    override 用 **!override**（替换而非追加）钉成 127.0.0.1:3100:3000。
    override 必须在仓库根才会自动合并，移走就失效。
    端口是分层差异、不是文档错误：上游 README 写 localhost:3000 对上游用户正确，本 fork 一律 3100；
    上游 README 的「Vercel 部署（1.1.x 及以前）」是版本史实说明，也不改。
  • 所有辅助端口都绑回环；3100 无鉴权，只能本机访问。要手机/他机预览得临时把 override 改成
    '3100:3000'（去掉 127.0.0.1 前缀）——这会暴露无鉴权服务，用完改回。
  • 挂载：openmaic-data:/app/data、openmaic-postgres；override 额外挂
    ./openmaic.yml:ro、ComfyUI workflow JSON、./public/brand:ro、.workbuddy/deliver/data:/data；
    render-service 挂 logs/render-metrics、logs/render-projects；sidecar 挂阿里云盘登录态目录。
  • public/ 只能挂子路径，不能整目录挂：会盖掉构建期生成的 standalone-player，离线单文件导出随即 404。
  • 渲染产物与 metrics 必须挂宿主 logs/：否则 compose recreate 之后内存 JobStore 与成片一起丢。

3. 三种 env 注入与三个生效时点

时点 来源 改了之后
构建期 Dockerfile 的 ARG → ENV，compose build.args 传入（ALPINE_MIRROR/NPM_REGISTRY/ALLOWED_FRAME_ANCESTORS + 12 个 NEXT_PUBLIC_*） 必须重建镜像
容器运行期 env_file: [docker-compose.defaults.env, .env.local]（后者覆盖前者）+ environment: 的 ${VAR:-默认} docker compose up -d --force-recreate openmaic，不要重建镜像
应用启动 openmaic.yml 的 ${VAR}（经 environment 从 .env 插值透传）+ 文件本体 strict 校验 重启服务；配错直接拒绝启动
  • NEXT_PUBLIC_* 是构建期常量，compose 的 env_file 不喂 build.args（源码注释原话），
    所以放进 .env.local 无效，必须在 .env / 命令行构建时提供。
  • .env（compose 变量插值）与 .env.local（容器 env_file）职责不同：
    docker-compose.defaults.env 的注释明确写「插值不来自 .env.local」。
  • openmaic.yml 的 ${VAR} 无默认值，缺失即启动失败；密钥不要写进 options（[[05-provider-and-slot-configuration]]）。
  • Dockerfile 存在两处参数不对称：ARG NEXT_PUBLIC_PI_CHAT_ENABLED 有 ARG 无 ENV；
    ARG INTERACTIVE_ASSET_BASE_URL 有 ENV 但 compose build.args 未传。改动前先核对。

4. 网络与代理

  • render 网络 internal:true + CAP_NET_ADMIN + iptables egress lockdown：渲染跑的是不可信 Chromium，
    必须断外网。
  • RENDER_SERVICE_URL 常驻，但能力探测走 /health：URL 存在 ≠ MP4 导出可用；
    video-export profile 关闭时降级为导出 ZIP 供本地 CLI 渲染。
  • slots.tts 在配置层是单指派（edge-tts:edge-tts，无 fallback 键）：起了 piper-tts 也不会自动接管 slots.tts。
    但 agent 运行时已有 provider failover（fork 提交 652ff977，lib/server/agent-runtime/scene-tts.ts:399-404,592-599）：
    主 provider 运行时失败会切到其他启用的服务端 TTS provider（piper 仍被过滤）。「单点无降级」只在配置层成立。
  • 国内构建三参数 ALPINE_MIRROR / NPM_REGISTRY / PIP_INDEX_URL；
    运行期 HTTPS_PROXY / NO_PROXY / ALLOW_LOCAL_NETWORKS（ComfyUI 走 host.docker.internal:8188）；
    provider 级 proxy 字段在 yml schema 内。NODE_OPTIONS=--no-network-family-autoselection
    用来关掉 happy-eyeballs，规避高延迟 LLM 端点的 250ms 候选窗口误判。
  • ComfyUI Desktop 跑在宿主 :8188，不在 compose 里。

5. 本机约定（fork 口径，非上游事实）

  • 配置只写 openmaic.yml + .env，不在设置页加 provider：workspace 层会按
    [[05-provider-and-slot-configuration]] 的优先级盖住 yml 默认值，且界面看不出值来自哪层。
  • 改 openmaic.yml 前先 cp 备份——它被 gitignore，坏了只能按
    lib/server/model-config/openmaic-yml.ts 的 strict schema 重建。
  • 客户部署 clone 的是 fork（github.com/voidvec/OpenMAIC），新机清单在 deploy/README.md §1–§8。

来源与可信度

docker-compose.yml / override / defaults.env / Dockerfile / .env.example 的静态核对，
deploy/README.md 与本机 .workbuddy/README.md 的现役链路速查交叉验证。
「TTS 不会自动接管」「3100 无鉴权」「必须备份 yml」属本机台账结论，标 ledger-derived 部分使用前请复现；
本页整体为源码可核对事实。构建期/运行期的分界另见 [[15-source-of-truth-and-layering-rules]] 的分层差异。
