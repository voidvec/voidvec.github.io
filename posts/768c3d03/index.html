OpenMAIC 数据模型与三层存储

发表于2026-11-11|更新于2026-11-11|AI辅助开发智能体应用
|浏览量:
项目/OpenMAIC/核心知识
OpenMAIC数据与运维进阶

结论：数据分三层——DSL 定义「课程长什么样」、PG 存服务端权威状态、
浏览器存设备相关的重产物与偏好。三者不互为备份，删掉任何一层都会丢不同东西。
owner 隔离不是靠查询时加 WHERE 就想起来，而是靠 provider 层强制绑定。

1. DSL 层（@openmaic/dsl）

  • 零依赖 keystone 包；JSON Schema 在构建期生成。
  • Stage{ outline, scenes[] }；scene.type = slide / quiz / interactive / pbl。
  • 职责分离：**validate* 只报告问题，normalize* 才修复**；migrate 按 DSL_MIGRATIONS
    ladder 升级版本。改结构时不要顺手在 validate 里修数据。
  • 导出面：slides、stage、interactive、pbl、pbl-v3、action、asset-manifest、
    runtime、media-address 等（dsl/src/index.ts），另有 ./schema/* 子路径。

2. Postgres 层

没有 ORM：直接 pg + 手写 DDL，表定义散在 packages/@openmaic/storage/src/*/pg.ts。

组 表
文档 document_folders(复合 PK owner_id,id)、document_stages、document_scenes、document_outlines、document_stage_revision、document_scene_revision
运行时 runtime_sessions、runtime_records
Agent 会话 agent_sessions、agent_session_events、agent_session_entries、agent_session_urls、owner_session_events
资产 asset_blobs、asset_entries、document_asset_refs、asset_root_refs、asset_blob_stages
其他 agent_user_skill、agent_session_materials、export_deliveries（交付台账，见 [[10-video-rendering-and-cloud-delivery]]）

migration 机制（pg-migrations.ts）：版本化 DDL + openmaic_schema_migrations 记 checksum，
applySchemaMigrations 用 session advisory lock 串行执行；SchemaVersionAheadError 会拒绝「新库旧代码」启动；
baseline transaction:false 逐句幂等；不支持 PgBouncer transaction 模式。
启动时由 lib/persistence/server-provider.ts 的 ensure*Schema 逐个调用。

一个容易踩的并发细节：revision 由触发器 + 伴随表维护，并用 pg_notify 唤醒 freshness SSE；
锁序必须 SR → SCR，否则死锁（document/pg.ts:251-284）。

3. 浏览器层

**设备库 maic-device-cache**（Dexie，lib/device-storage/database.ts，已核对版本声明）：

store 键 版本
audioFiles id, stageId v1
mediaFiles id = ${stageId}:${mediaRef} v1
snapshots ++id v1
voiceProfiles、autoVoiceCache、meta — v1
courseThumbnails [ownerKey+stageId], usedAt v3
renderedVideos stageId, createdAt v4

v2 删除了 imageFiles；v3 引入缩略图（键是 ownerKey 单向摘要，不是 ownerId 本身）；
v4 引入成片视频。旧库 MAIC-Database（Dexie，只读，供一次性导入）以及
maic-documents / maic-runtime / maic-asset-pool 属遗留层（lib/legacy-browser-storage/）。

SDK 的浏览器实现另有自己的 object store：stages/scenes/outlines、sessions/records、assets/blobs。
KVStore 走 localStorage（namespace maic），只有 account scope 有 HTTP 后端。

存哪里 数据
PG 课程文档、generation run、runtime、资产字节（Pg/S3）、素材、技能、workspace 配置、交付台账
浏览器 设备缓存、缩略图、成片 MP4、undo 快照、音色档案、settings、device KV

浏览器侧成片留底的根因（rendered-video.ts 注释）：一次 31 分钟渲染因服务重启不可取回，
而 render-service 只保留内存 job + 临时目录，重启即丢，所以浏览器交付包链路必须留底。
自动上云链路是另一条路：lib/server/deliver/pipeline.ts 轮询 render-service 下载 MP4
写进服务端 dataRoot，不经 IndexedDB（[[10-video-rendering-and-cloud-delivery]]）。

4. owner 隔离

  • ownerId 由 cookie / credential 解析（lib/server/identity/with-owner.ts）。
  • server-provider.ts **特意不提供无边界的 PgDocumentStore**，而是
    createOwnerBoundDocumentStore + fenceOwnerWrite，把 owner 钉在 provider 构造时。
  • 表 PK 直接带 owner_id（复合主键），跨 owner 读取在 schema 层就不成立。
  • 贡献规则（AGENTS.md）把「courses / sessions / materials / settings 的读写必须留在请求 owner 内」
    列为评审重点，改持久化代码时先想清楚这条。

来源与可信度

dsl/src/index.ts、storage/src/pg-migrations.ts、storage/src/*/pg.ts、
lib/device-storage/database.ts:170-215（已抽查）、lib/persistence/server-provider.ts、AGENTS.md。
均为静态源码核对；表名与 store 名可直接 grep 验证。发布包变更需遵循
CONTRIBUTING.md#changing-a-published-package 的版本规则（见 [[09-testing-ci-and-quality-gates]]）。
