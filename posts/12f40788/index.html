OpenMAIC Provider 与 Slot 配置体系

发表于2026-11-12|更新于2026-11-12|AI辅助开发智能体应用
|浏览量:
项目/OpenMAIC/核心知识
OpenMAIC实践指南进阶

结论：模型能力不是「在设置页填一个 key」，而是 openmaic.yml 里的 providers（有哪些供应商）

  • slots（哪个能力用哪个模型） 两棵树；设置页是第二层覆盖。resolveSlot 的优先级有一个
    反直觉规则：用户写在祖先 slot 上的赋值，压得过更靠近目标 slot 的服务端默认值。

1. 文件与校验

入口 lib/server/model-config/openmaic-yml.ts，默认读cwd 下 openmaic.yml，
可用 OPENMAIC_CONFIG 指定。instrumentation.ts 在启动时调 validateModelConfiguration()，
配错直接拒绝启动——不是运行时才报错。

顶层字段 含义
providers 供应商声明，.strict()
slots 能力 → 模型指派
lock 'all' 或 slot 名数组，锁定子树
allowUserKeys 默认 true
sandbox 沙箱配置（另有 lib/sandbox/config-schema.ts）
brand 白标（见 [[11-white-label-and-aigc-compliance]]）
policy z.never() —— 主动拒绝旧字段，不是「暂时没实现」

providerSchema（strict）：preset（必填）、apiKey / baseUrl(z.url) / models /
proxy(z.url) / credentials / options / voices。
assignmentSchema：null | "providerId:modelId" | { model, thinking, fallback, api, contextWindow }。
thinkingSchema 六字段：mode / effort / level / enabled / budgetTokens / excludeReasoningOutput。

三个防呆：

  1. ${VAR} 无默认值语法——变量未设置或为空 → environment variable X is not set，启动失败。
    密钥所在路径记入 secretPaths，不回显。
  2. options 里名字含 key/secret/token/password 的键被拒，防密钥经设置页泄漏。
  3. crossCheck() 校验 preset 存在 / capabilities 匹配 / requiresBaseUrl / voices 仅 TTS /
    fallback 仅 chat / api·contextWindow 仅 agent / thinking effort 兼容性 / lock 指定的 slot 必须真写在 slots 里。

2. 覆盖优先级（resolve-slot.ts，已核对源码注释）

两层：deployment（openmaic.yml，服务端默认值 + 声明 lock）与 workspace（web 设置页）。

SlotSource = 'default' | 'workspace' | 'locked'。写入侧 applyModelSettingsChange 对 locked
抛 SLOT_LOCKED；密钥只写不读，读取走 maskKey。

实操含义：配置只写 openmaic.yml + .env，不要在设置页加 provider。
一旦设置页留了旧值，它会按上面的规则盖住 yml 里的默认值，而且很难从界面看出「这个值来自哪一层」。

3. slot 树

lib/config/model-slots.ts：

18 个 LLM_STAGES 经 STAGE_SLOTS 映射到具体 slot；生成管线按阶段取 slot（[[03-classroom-pipeline-and-async-task-contract]]）。

4. 三个已经废掉 / 容易记错的东西

旧认知 现状
MODEL_ROUTES 决定模型路由 已废除。只剩浏览器 x-model-routes header，且仅在 slot 未分配时被 consult，fallback 被强制丢弃（lib/server/model-routes.ts）
provider.models 是设置页下拉列表 它是服务端凭据 provider 的授权 allowlist 主干（model-authorization.ts:69-99）；授权集合还并入 config.slots 显式引用的 model / fallback，只有 x-model-routes 的 fallback 被强制丢弃
设置页能覆盖锁定项 不能，写操作抛 SLOT_LOCKED

5. 新增一个服务商的检查清单

  1. lib/config/provider-presets.ts 确认/新增 preset（getProviderPreset、capabilities、requiresBaseUrl、registryId），
    已退役 preset 由 lib/server/model-config/deployment-layer.ts 处理。
  2. openmaic.yml 的 providers 声明 preset + apiKey/baseUrl/models/proxy/voices（TTS 才允许 voices）。
  3. slots 把目标能力指到 "providerId:modelId"；要停用一个能力写 null，不要删键。
  4. 密钥走 .env 的 ${VAR} 插值，不要写进 options。
  5. 重启（配置只在启动时解析）；若改的是 NEXT_PUBLIC_*，要重建镜像（[[08-deployment-topology-and-config-layering]]）。
  6. 用 /api/provider/probe-models、/api/verify-{model,image-provider,video-provider,pdf-provider} 验证。

6. 音色是特例

edge-tts.voices 这类音色列表是偏好而不是模型 slot：配置里登记 5 个对外可选中文音色，本机实测全集 8 个（含方言，见 .workbuddy/docs/2026-11-03-edge-tts-setup-guide.md），两个数字口径不同、不是冲突：音色存浏览器 settings.ttsVoice，
生成时由浏览器逐条调 /api/generate/tts 带 ttsVoice；generate-classroom 请求体不收该字段。
音色在生成时烧进音频，改配置不会改变已有课堂。browser-native-tts 更是只能客户端合成。

来源与可信度

lib/server/model-config/resolve-slot.ts:1-22 注释已抽查（优先级、无 vendor 兜底为源码原文）；
其余来自 openmaic-yml.ts、settings.ts、model-slots.ts、provider-presets.ts、
model-routes.ts、openmaic.example.yml 的静态阅读。本机 openmaic.yml 实例值与
「不在设置页加 provider」的约定属 fork 部署口径，见 [[08-deployment-topology-and-config-layering]] 与 [[15-source-of-truth-and-layering-rules]]。
