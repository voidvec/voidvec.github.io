OpenMAIC 导出能力矩阵与交付包生成

发表于2026-11-12|更新于2026-11-12|AI辅助开发智能体应用
|浏览量:
项目/OpenMAIC/核心知识
OpenMAIC模块参考进阶

结论：产品导出的是零散文件，客户拿到的是按 SKU 重新编号的交付包——这是两个不同的层，
中间隔着 lib/export/delivery-bundle.ts。不要把「导出成功」当成「交付完成」。

1. 四条导出线

线 入口 / 实现 产物 关键限制
PPTX use-export-pptx.ts + pptxgenjs；占位页 pptx-scene-placeholders.ts 可编辑 deck 「仅幻灯片」= slidesOnlyDeck(slideCount)；含占位页版本会把 quiz/interactive/PBL 变成索引页
单文件 HTML buildStandaloneHtmlExport（standalone-html/build-standalone-html.ts），format:'auto' 离线整课连播页 单文件上限 400 MB、警告阈值 100 MB；超限自动回退 zip；includeNarration 决定是否嵌音视频
.maic.zip buildClassroomExportZip（JSZip，manifest.json + files） 课程资源包 buildClassroomExportSnapshot 让 HTML 与 zip 共用同一快照（mediaIndex、媒体/视频封面收集），避免二次生成漂移
MP4 buildExportZip：compileVideoTimeline → emitHyperframes → collectVideoAssets → packageVideoZip 渲染用 ZIP / 成片 useExportVideo 下 ZIP 给本地 CLI；useRenderVideo 上传 render-service 出片

导出菜单入口在 components/stage/header-controls.tsx（不在 lib/export/）。

2. 体积与降级

lib/export/standalone-html/limits.ts：

  • STANDALONE_HTML_MAX_BYTES = 400 MB；超过 → 自动转 zip 变体（classroom.html + media 目录，4 GiB 上限）。
  • zip 变体里的 classroom.html 自身仍受 400 MB 限制（交互媒体内联），不是「转 zip 就无限」。
  • StandaloneHtmlTooLargeError 带 kind: 'single-file' | 'page' | 'archive'，用于区分是哪一层超了。
  • 交付编排层对 06 单文件采取 best-effort：超限时回退 zip 就干脆不出（zip 套 zip 要解两层），
    见 [[13-delivery-package-spec]]。

3. 视频相关 API

路由 行为
POST /api/export-video/render multipart 流式转发，MAX_UPLOAD_BYTES = 300 MB，SUBMIT_TIMEOUT_MS
GET / DELETE /api/export-video/render/[jobId] 轮询（pollIntervalMs 3000）/ 取消
GET .../download redirect:'manual'：优先 302 预签名直传，否则流式 video/mp4
GET /api/export-video/capability 能力探测
POST /api/deliver/upload raw body（非 multipart，避免 40 MB formData() 缓冲）；MP4 不走这里，由 render 代理按 jobId 入队

4. 成片从哪来

render-service 只保留内存 job + 临时目录，重启即丢。浏览器交付包链路因此把成片存进
IndexedDB renderedVideos（lib/device-storage/rendered-video.ts 的 saveRenderedVideo，
调用点 lib/store/video-render.ts）：导出时用 loadRenderedVideo(stage.id) 取回塞进 bundle
（use-export-pptx.ts），按 stageId 一门课一条。
自动上云链路（DELIVER_ENABLED）不走这里：lib/server/deliver/pipeline.ts 轮询 render-service
下载 MP4 写进服务端 dataRoot，页面提交 job 后即无关。
详见 [[04-data-model-and-three-tier-storage]] 与 [[10-video-rendering-and-cloud-delivery]]。

5. 交付包是「二次组装」

lib/export/delivery-bundle.ts（已抽查注释）：

  • 定位：把应用各自为政的导出文件，组装成买家能直接打开的一个编号文件夹；
    是 bench/pack-delivery.py 的浏览器等价物。纯函数、无 store/i18n/DOM，可在 worker 里跑。
  • DeliverySku = 'lesson' | 'contest'；唯一差异是有无成片：lesson 卖成片，
    contest 不含成片，因为赛区要求教师本人出镜，纯 AI 成片过不了初审。
  • singleHtml（带旁白单文件）只给不含视频的档：那档客户要自己录人像，唯一不能给的东西是
    「能自己播放并说话」的东西，而带旁白的单文件恰好就是这个；教学档的旁白已烧进 MP4。
  • 常量：DEFAULT_PAGES_DIR = '交互页面'、DEFAULT_FORMAT_DIR = '格式件'、
    DEFAULT_USAGE_NOTE_NAME = '00_使用说明.txt'、MAX_TITLE_LENGTH = 60；
    bundleTitle() 清洗 Windows/macOS/云盘 CLI 的非法字符。
  • 资源包里页面在 interactive/、quiz/，bundle 里归到 交互页面/；deck 的超链仍指向包内原路径，
    所以有 relinkDeck 重写——光用相对路径不够。
  • formatFiles 两档都出，但内容不同：有视频档写 ffprobe 实测参数，无视频档写录制目标参数。

双档编号语义见 [[13-delivery-package-spec]]；件数、QA、云盘链接回 .workbuddy/xianyu-kejian/README.md 查。

6. PPTX 占位页：两条链路

两条导出链路，不是两个互相矛盾的口径：

链路 形态 依据
产品「导出交付包」 带占位页 + 强制相对链接，不画二维码 / 在线按钮 use-export-pptx.ts:1873-1878 的 buildPack(includePlaceholders, true)
散件 PPTX / 教学资源包（bench/export-artifacts.mjs） 「仅幻灯片」 export-artifacts.mjs:147,155

旧铁律「必须选仅幻灯片否则 localhost 二维码死链」只对散件或独立 PPTX 的在线模式成立
（lib/config/export-link-preference.ts 默认在线、占位页会画 QR）；产品交付包已硬性改为相对链接，
菜单默认项也是「含占位页（推荐）」。两条链路属分层差异，见 [[15-source-of-truth-and-layering-rules]]。

来源与可信度

lib/export/delivery-bundle.ts:1-107 已抽查；其余来自 use-export-{pptx,html,classroom}.ts、
pptx-scene-placeholders.ts、standalone-html/{build-standalone-html,limits}.ts、
video-export-app/build-export-zip.ts、app/api/export-video/** 的静态阅读。
PPTX 占位页冲突为文档事实（不是代码结论），已在 §6 显式标注。
