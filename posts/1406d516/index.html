环境变量与 Postman 集合转换

发表于2026-11-25|更新于2026-11-25|框架库Qt框架
|浏览量:
项目/qt-network-request/配置与运行
qt-network-request实践指南进阶

证据基线：master @ 6c25067；未运行 GUI 或真实 Postman 文件兼容性测试。

1. 背景

环境变量、请求集合和 Postman 转换用于把一次性请求变成可复用资产。它们位于公共库功能层，并由 QtRequester 调用。需要特别注意：Collection 是普通 C++ 树，不是 Qt 视图模型；Postman 转换是部分字段映射，不是完整 v2.1 schema 实现。

2. 核心结论

  1. 变量语法为 {{key}}，key 允许字母、数字、下划线、点、连字符，且不能包含内部空白。
  2. 替换是单次遍历：未知变量保留原占位符；变量值中若再次出现 {{...}} 不会被递归替换。
  3. 替换覆盖 URL、Header 值、文本 Body、Query 值和认证字段；不替换 Header 名、Query 名或二进制 Body。
  4. 库只接收一张变量 Map，没有全局/集合/系统环境的优先级合并；优先级由 GUI 选择哪张 Map 决定。
  5. EnvironmentStore 支持多个命名环境和 active 名称的 JSON 存取，但 Store 本身不负责加密或自动保存。
  6. Collection 支持 Folder/Request 树、UUID、查找、增删和 JSON 存取；QtRequester 只暴露了基础集合操作。
  7. Postman v2.1 转换支持集合名、嵌套文件夹、method、URL raw/string、Header key/value、raw Body 和 auth 字段透传；其余大量结构会丢失或无法转换。

3. 环境变量替换规则

3.1 语法与匹配

正则表达式为 \{\{(\w[\w.-]*)\}\}：

  • 合法示例：{{host}}、{{api.key}}、{{client-id}}。
  • 不支持 key 内部空白。
  • 同一文本中的多个占位符会依次处理。
  • 未找到 key 时追加原始匹配串，不报错、不删除。

依据：source/features/environment.cpp:38-61。

3.2 覆盖字段

字段 是否替换 说明
url 是 整个 URL 字符串
headers 值 是 Header 名不替换
body 是 文本 Body
binaryBody 否 明确不修改二进制数据
queryParams 值 是 Query 名不替换
Basic 用户名/密码 是 认证字段单独处理
Bearer Token 是 —
API Key 名称/值 是 Header 名最终仍由 API Key 配置决定
OAuth2 全部凭据字段 是 Token URL、client、scope、用户名、密码、refresh token

依据：source/features/environment.cpp:64-113。

3.3 注释与实现差异

源码注释声称可以用四个花括号转义字面量 {{...}}，但实际算法没有对应转义分支：{{{{key}}}} 会按正则匹配内部片段并进行替换。需要保留字面量时，不应依赖该注释，应通过运行测试确认行为或避免使用冲突占位符。

依据：source/features/environment.cpp:42-61,74-77。

4. 命名环境与持久化

EnvironmentStore 的内存结构是环境列表加 active 名称：

  • load() 读取 JSON 对象中的 active 和 environments。
  • 每个环境包含 name 和 variables 对象。
  • activeVariables() 返回 active 名称对应环境的变量；找不到时返回空 Map。
  • save() 将当前状态写回 JSON。

依据：source/features/environmentstore.cpp:38-95,106-129。

关键规则

  • 变量值是普通字符串，没有 secret 标记、加密或权限控制。
  • Store 的 setActiveName() 只修改内存，不自动写文件。
  • 库不定义环境覆盖优先级；如果未来加入系统环境、集合变量或全局变量，需要明确冲突规则。
  • 文件损坏、字段缺失或值不是字符串时，当前解析可能得到空值或默认结构，调用者应校验导入结果。

5. Collection 数据模型

5.1 节点结构

CollectionItem 只有两类：

  • Folder：包含 children。
  • Request：包含 requestJson。

每个节点有 id、name，请求节点保存与单请求 JSON 相对应的字段。Collection 维护一个名为 root 的根文件夹。

依据：include/collectionmodel.h:36-52,95-96。

5.2 已实现操作

  • 设置/读取集合名。
  • 按 ID 查找节点。
  • 在指定父节点下新增 Folder 或 Request。
  • 按 ID 删除节点。
  • 生成无花括号 UUID。
  • 整体 JSON 加载/保存和单节点序列化。

依据：include/collectionmodel.h:54-97、source/features/collectionmodel.cpp:43-235。

5.3 不是模型视图

Collection 不继承 QAbstractItemModel。GUI 树是示例应用根据集合数据自行构建的界面，因此模型修改不会自动反映到界面；刷新是应用层职责。

6. Postman v2.1 覆盖矩阵

Postman 结构 导入 导出 当前行为
info.name 是 是 集合名映射
嵌套 item 文件夹 是 是 递归转换
request.method 是 是 缺省 GET
URL 字符串 是 否 导入接受 string
URL 对象 raw 是 是 只读写 raw
URL host/path/query/variable 否 否 不重建结构化 URL
Header key/value 是 是 丢弃 enabled、description、type 等属性
Raw Body 是 是 非空 raw 才写入
form-data / urlencoded / file / graphql 否 否 不转换
auth 对象 透传 透传 不做标准 auth 语义转换
脚本、事件、集合变量 否 否 不处理
文件夹级认证 否 否 不处理
内部稳定 ID 否 否 导出不保留内部 ID

依据：source/features/postmanconverter.cpp:36-110,113-222。

6.1 “双向导入导出”的准确含义

当前实现是基础集合结构和部分请求字段的双向映射，不是无损 Postman 往返：

  • 导出 URL 只写 raw，Query 参数不单独输出。
  • 非 raw Body 不会转换。
  • auth JSON 可以保留，但 QtRequester 自定义 auth 结构与标准 Postman auth 结构不一定能互相理解。
  • 导入空文档或缺少 info/item 的结构仍可能返回成功；不能把 ok=true 当作完整 schema 校验。

依据：source/features/postmanconverter.cpp:184-221、source/features/postmanconverter.cpp:73-110。

7. 使用与维护规则

  1. 导出前检查 Body 类型：form-data、urlencoded、file、graphql 不应假定能保留。
  2. 导出前检查 URL Query：结构化 Query 可能只保留在 raw URL 中。
  3. 区分“文件可打开”与“数据完整”：对导入结果做名称、方法、URL、Header 和认证抽查。
  4. 不要在共享集合中放生产密钥：当前没有 secret 字段隔离和脱敏导出。
  5. 变量冲突由调用方管理：库不合并多级环境，GUI 需要明确当前 active Map。
  6. 保持 Collection 与 GUI 刷新同步：模型变更后更新树和当前请求编辑器。
  7. 不要依赖花括号转义注释：以实际替换算法和测试为准。
