OpenMAIC 课堂生成管线与异步任务契约

项目/OpenMAIC/核心知识
OpenMAIC接口与协议进阶

核心结论：/api/generate-classroom 不是独立的生成服务，而是 generation run 的一层兼容 view
（jobId === runId）。所有生成步骤由服务端 PG 记录 + lease worker 驱动，浏览器只负责 start、
订阅 SSE 事件、发命令；唯一例外是 browser-native-tts 必须客户端合成。

1. 启动契约

POST /api/generate-classroom → app/api/generate-classroom/route.ts（已抽查源码）

项 值
请求体 只有 { requirement, materialIds? }（parseClassroomJobBody）
显式拒绝 pdfContent；outlineReview 强制 'auto'
成功 202 + classroomJobView(run, ...)
400 INVALID_REQUEST / MISSING_REQUIRED_FIELD / MISSING_MODEL（预检 outline/actions/content 所需 slot）
429 ACTIVE_RUN_LIMIT（每 owner 活动 run 达上限）
500 INTERNAL_ERROR，错误文本不入网
401 INVALID_CREDENTIAL；宿主可挂 authorizeStart 自定义拒绝

能力不由请求决定：交互引擎、任务引擎、出图/出视频是否启用，跟随服务端配置，不随 body 传。
这与「我在请求里加个开关就能开视频」的直觉相反。

2. 身份与轮询

  • withRequestOwner 先解析 owner，再把 Set-Cookie 附到每一个响应，含 4xx/5xx。
    否则客户端拿到 400 重试时会换一个匿名 owner，素材与课程对不上。
  • cookie：anonymous_id，400 天，UUID v4，anon: 命名空间（lib/server/identity/anonymous-cookie.ts）。
  • 轮询：GET /api/generate-classroom/[jobId]，pollIntervalMs = 5000（CLASSROOM_JOB_POLL_INTERVAL_MS），
    返回 status / step / progress / done / retryable / result.url = /classroom/{stageId}。

3. 状态机

  • paused 不是终态：job 会报 failed 但带 retryable: true，
    POST /api/generation-runs/{id}/retry { commandId } 从失败步原地续跑。
  • outlineReview 三态 wait / countdown（2500ms 自确认，本接口强制 auto）/ auto；
    LIMITED_RUN_STATES 不含 awaiting 与 paused。
  • 错误码映射：runFailureCode → GENERATION_FAILED / RATE_LIMITED / UPSTREAM_ERROR /
    PROVIDER_QUOTA_EXHAUSTED / INTERNAL_ERROR。
  • 限额（run/config.ts）：全局并发 4、每 owner 活动 2、等待队列 10、日志保留 24h。

4. Plan 步骤与 checkpoint

RunStep（run/plan.ts）实际命名：

三个反直觉点：

  1. media 不是 plan 步骤，checkpoint 键为 media:<elementId>，借 step 表存放，
    这样 takeover 才能定位到已提交但还没回来的媒体任务。
  2. **视频 provider 提交后 checkpoint 存 taskId**，接管时续等而非重复提交，避免重复计费/重复渲染。
  3. narration 步骤与「把场景追加进课程」在同一事务提交，避免音频只存在于 checkpoint 而课程里没有。

5. 超时与失败语义

lib/server/generation/run/deadline.ts：

步骤 截止时间
materialAnalysis / research / outline / sceneContent / sceneActions 300 s
agentProfiles 120 s
narrationClip 30 s
MEDIA_DEADLINE_MS 300 s

withDeadline() 抛 StepTimeoutError，statusCode = 504，且被当作可重试失败。
注释说明这些值刻意对齐 1.1.x 旧 API 路由超时。其他超时：LLM_FETCH_TIMEOUT_MS = 15 min
（lib/ai/providers.ts）、RENDER_JOB_DEADLINE_MS（compose 里 9000000，见 [[10-video-rendering-and-cloud-delivery]]）。

图片/视频失败、无旁白语音不令 job 失败，只计入 result.warning。所以「生成成功」不等于
「所有媒体都齐」，交付前必须做 QA（客户侧清单见 .workbuddy/xianyu-kejian/README.md）。

6. 服务端 / 浏览器边界

位置 职责
服务端 run 记录、lease worker、全部 plan 步骤、LLM、大部分媒体生成
浏览器 start 请求、SSE 事件、命令（confirm/hold/retry）、**browser-native-tts 合成**
外部 MP4 渲染不属生成管线，由 render-service 单独提交

browser-native-tts 是唯一被服务端生成管线明确拒绝、必须客户端合成的 provider
（run/steps/narration.ts）。这也解释了为什么音色选择只能由浏览器逐条调 /api/generate/tts 带
ttsVoice，generate-classroom 请求体里根本没有该字段。

7. 相关 API 分组（速查）

generate-classroom{,/capabilities,/[jobId]}；generation-runs{,/events,/[id],/[id]/{confirm-outline,hold-outline,retry,events}}；
generate/{image,tts,video,voice}；agent/{runtime,sessions,skills,owner-events,...}；
stages/[id]/{manifest,scenes,status,publish,unpublish,freshness,generation-complete,roster}；
materials/**、proxy-media、parse-pdf、transcription、quiz-grade。

GET /api/generate-classroom/capabilities 是 owner-free 只读，但仍受同一个 access-code 网关约束。

来源与可信度

app/api/generate-classroom/route.ts 全文已抽查；其余来自
lib/server/generate-classroom-job.ts、run/{plan,engine,deadline,config,types,failure-code,media}.ts、
lib/server/identity/{with-owner,anonymous-cookie}.ts 的静态阅读。未做运行时实测，
状态码与轮询字段以源码为准；如果修改了 run/config.ts 或 deadline 常量，本页数值需同步。
