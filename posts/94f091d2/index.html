OpenMAIC 测试、CI 与质量门禁

发表于2026-11-13|更新于2026-11-13|AI辅助开发智能体应用
|浏览量:
项目/OpenMAIC/核心知识
OpenMAIC测试与基准进阶

结论：三条测试轨道互不替代——vitest 单测 / Playwright e2e / eval/ 评测，
外加构建前的静态门禁。项目没有 husky、没有 pre-commit、没有 lint-staged，
所有门禁集中在 GitHub Actions，因此本地 pnpm check + pnpm lint 必须自觉跑。

1. 三条测试轨道

轨道 配置 入口
单测（Vitest 4） vitest.config.ts：include ['tests/**/*.test.ts']，setup tests/setup-env.ts + tests/pg-contract-database.ts；另有 8 个包级 vitest.config 与 render-service/vitest.config.ts pnpm test / pnpm test:local
评测（独立轨道） vitest.eval.config.ts：include ['tests/**/*.eval.test.ts']；eval/ 六条线（orchestration / outline-language / pbl-v2-planner / whiteboard-layout / whiteboard-shapes / shared），每条自带 runner + judge + reporter + scenarios JSON pnpm eval:*
E2E（Playwright） playwright.config.ts：testDir './e2e/tests'，仅 chromium，baseURL http://localhost:3002，timeout 30 s，CI globalTimeout 13 min / retries 2 / workers 2；webServer 在 CI 用 pnpm start、本地用 pnpm dev pnpm test:e2e

e2e/tests/ 约 60 个 spec（pbl-v3-*、mobile-*、interactive-*、回归编号用例），
e2e/pages/ 是 Page Object，e2e/fixtures/ 提供 server-seed / mock-api / media-stubs / 交互 host stubs 等。

一个构建期陷阱：Playwright 依赖的 NEXT_PUBLIC_MAIC_EDITOR_ENABLED、
NEXT_PUBLIC_COURSEWARE_REFERENCE_ENABLED 必须设在 CI 的 pnpm build 步，
只放到 pnpm start 的 env 里无效（[[08-deployment-topology-and-config-layering]] 的构建期常量规则）。

其他脚本：test:package-tarballs（制品冒烟）、check:i18n-keys、check:node-engine、
check:package-versions、check（prettier）、lint（eslint）、db:up/db:down。

2. 静态门禁（eslint.config.mjs）

flat config，继承 eslint-config-next/core-web-vitals + /typescript；按目录大量定制：

  • packages/@openmaic/{renderer,storage,generation}、lib/choreography、
    lib/video-export*、lib/pbl/v2/operations/kernel 上有 no-restricted-syntax / no-restricted-imports；
  • 全局 AI_SDK_DYNAMIC_IMPORT_BAN 禁止 await import('ai')；
  • @next/next/no-img-element 关闭，no-unused-vars 定制。

这些规则体现的是架构边界（哪些层不许互相 import），不是代码风格偏好，改之前先看规则指向的目录。

3. CI：8 个工作流

工作流 干什么
ci.yml 主力。lint job 并行 4 检：pnpm check(prettier) / pnpm lint(eslint) / npx tsc --noEmit / pnpm check:i18n-keys；外加 node-engine、package version bumps、internal dependency ranges、.github/scripts/*.test.mjs。unit（vitest --shard=x/4）、package-tests、storage-tests（PG 契约 typecheck + test）、ci-gate 聚合、render-service（typecheck + test + docker build）、e2e（3 分片，前置 pnpm build + browser vitest + hyperframes lint）、main-image（buildx）
docs-build.yml 文档站静态导出 pnpm build
storage-pg-contract.yml Storage / App-domain PostgreSQL 契约测试
publish-packages.yml 版本校验 → 构建 → pack → verify artifacts → typecheck/test → test:package-tarballs → npm Trusted Publishing
publish-openmaic-skill.yml ClawHub CLI 发布 skill（preview/publish，仅 main）
issue-triage.yml Codex 自动分析 issue
flaky-report.yml 定时汇总 flaky 报告
pr-reminders.yml 每日提醒卡住的 PR

分片（单测 4 / e2e 3）+ globalTimeout 的设计意图：即使整体超时，也能报出已完成的用例名并上传报告。

4. 贡献约束

  • CONTRIBUTING.md#changing-a-published-package：改了 packages/@openmaic/* 的已发布行为必须带版本 bump；
    ci.yml 的 check-package-version-bumps.mjs 会拦。
  • AGENTS.md 给自动评审定的重点：owner scoping、storage schema 对已部署库的兼容性、
    provider 中立（共享层不硬编码厂商）、服务端请求用户 URL 必须走 URL guard；
    P1 只给「运行时产生错误行为」的问题，文档措辞最多 P2。

5. 本机测试通道（台账，未复现）

.workbuddy/memory/topics/repo-ci-test.md 记载：本机用宿主 npm run test:local 直跑，
镜像链已废；Windows 上有一批平台性失败（记为 36 个），还有 Bash PATH 丢 usr/bin、
Playwright 自带 Chromium 会被删等问题。

这些是 2026-11-03 带判据的实测基线（1081 文件 / 13911 用例，13 个失败文件均与本地提交无关，
且 origin/main worktree 同样红，见 .workbuddy/memory/topics/repo-ci-test.md:58-64），
该基线未重跑复现。它不是「从未验证的猜测」，而是「有实测依据、但可能已过期的基线」；
引用前跑一次 pnpm test:local 记录当前实际失败数与原因，再更新本段与 缺口清单。

来源与可信度

package.json 全部 scripts、vitest.config.ts / vitest.eval.config.ts / playwright.config.ts/
eslint.config.mjs / .github/workflows/*.yml 的静态核对；AGENTS.md、CONTRIBUTING.md 原文。
未执行任何测试或 CI。§5 是台账转述（篇内显式标注），其余部分为源码静态核对；引用 §5 前需复现。
