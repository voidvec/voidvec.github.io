OpenMAIC 视频渲染与自动上云交付

发表于2026-11-13|更新于2026-11-13|AI辅助开发智能体应用
|浏览量:
项目/OpenMAIC/核心知识
OpenMAIC实践指南进阶

结论：这是一条 fork 私有、默认关闭 的能力，上游 README 零覆盖。
lib/server/deliver/config.ts 的注释把设计意图写得很直白：它驱动阿里云盘 sidecar + 飞书群机器人，
所以「不主动要求就完全关闭」——上游部署不设这些环境变量时，不建表、不起 worker、不发任何外联请求。

1. 为什么配置走环境变量而不是 openmaic.yml

config.ts:1-13（已抽查原文）：

openmaic.yml 的 schema 是 strict 的，为「上游根本不发货的功能」加一个 deliver: 块，
就得连 schema、example、文档一起改。所以整条流水线只读环境变量。

这条决策可以直接推广：fork 私有能力一律走 .env + compose environment，不碰上游 strict schema。
同理见 [[05-provider-and-slot-configuration]] 与 [[08-deployment-topology-and-config-layering]]。

2. 开关与参数

变量 默认 / 行为
DELIVER_ENABLED 未设 / 0 / false → 整条流水线关闭
DELIVER_SIDECAR_URL / DELIVER_SIDECAR_TOKEN 缺任一只是 warn 并把功能关掉，不致命（上游部署没跑 sidecar 时是正常状态）
DELIVER_DATA_ROOT / DELIVER_CLOUD_ROOT sidecar 可读取根 / 云盘根；Next 侧必须把产物写进 dataRoot 树内
FEISHU_WEBHOOK_URL / FEISHU_WEBHOOK_SECRET 飞书自定义机器人 + HMAC 签名
DELIVER_{POLL_INTERVAL,RENDER_POLL,MAX_ATTEMPTS,RETRY_DELAY}_MS 5000 / 20000 / 4 / 60000

instrumentation.ts 在启动时拉起后台 worker；lib/persistence/export-deliveries.ts 的
export_deliveries 表是交付台账（format 含 mp4），记录每次上云的状态与重试次数。

3. 渲染服务与成片落点

  • render-service 是独立 Node 服务（profiles: [video-export]），render 网络 internal:true
    • CAP_NET_ADMIN + iptables egress lockdown——它跑的是不可信 Chromium，必须断外网。
  • JobStore 在内存、产物在临时目录，重启全丢。触发留底设计的事故写在源码注释里：
    一次 31 分钟渲染因服务重启不可取回。
  • 成片有两条落点，别混成一条链路：
    • 浏览器交付包链路 → IndexedDB renderedVideos（lib/device-storage/rendered-video.ts），
      按 stageId 一门课一条，导出时由浏览器取回；
    • 自动上云链路（DELIVER_ENABLED）→ lib/server/deliver/pipeline.ts 轮询 render-service
      下载 MP4 写进服务端 dataRoot，不经浏览器；pipeline.ts 注释明确「浏览器曾是成片唯一落点」，
      页面提交 job 后即无关。
  • 交付上传入口按载体分开：
    • MP4：服务端 worker 按 render_job_id 取回再上云（页面关掉也能交付）；
    • PPTX / HTML / ZIP：浏览器 POST /api/deliver/upload，只收这几类，
      用 raw body 而非 multipart（避免 40 MB formData() 缓冲）；
    • srt / docx / md / png：走 sidecar 共享卷直传，不经过该路由。
  • app/api/export-video/render/route.ts 的提交上限 300 MB；download 优先 302 预签名直传。
    详见 [[07-export-capability-matrix-and-delivery-package]]。

4. sidecar 的三重边界

deploy/deliver-sidecar/server.mjs：

边界 实现
路径白名单 assertInsideDataRoot：localPath 必须落在 DATA_ROOT 内，拒绝穿出
共享密钥 每个请求校验 x-deliver-token
分享模式 **拒绝 mode 3**（快传一次性链接）；统一 aliyunpan share -mode 1 -time 0（私密 + 永久）

接口：GET /health、POST /upload、POST /share；
UPLOAD_TIMEOUT_MS / SHARE_TIMEOUT_MS 分别限超时；SHARE_URL_RE / SHARE_PWD_RE / UPLOAD_OK_RE
解析 CLI 输出拿链接与提取码。镜像内置 aliyunpan CLI（deploy/deliver-sidecar/Dockerfile）。

5. 通知链路

worker → sidecar 上传 + 分享 → 飞书自定义机器人（HMAC-SHA256 签名）推卡片，
卡片里带「链接 + 提取码」。卖家从飞书复制后发给闲鱼买家，链接与提取码分两条消息发
（copy/xianyu-link1-299.txt:153 与 memory/topics/business-xianyu-todo.md:35 亦载明，已核到）。
同课复用唯一 share_url，改稿出 v2 但客户手里的课程目录链接不变（客户侧目录约定见 .workbuddy/xianyu-kejian/README.md）。

6. 本机编排脚本（指针）

一键编排由 .workbuddy/bench/make-course.mjs 串起校验、渲染、散件导出、说明、组包与上云；
命令与参数属本机 runbook，回脚本 --help 与 .workbuddy/runbooks/ 查，本库不维护命令清单。

来源与可信度

lib/server/deliver/config.ts:1-80 已抽查原文；其余来自 sidecar.ts、export-deliveries.ts、
instrumentation.ts、deploy/deliver-sidecar/server.mjs、docker-compose.override.yml、
rendered-video.ts、app/api/deliver/upload/route.ts 的静态阅读。
§6 为脚本指针；「链接与提取码分开发」已在 copy / topics 核到，客户侧口径见 .workbuddy/xianyu-kejian/README.md。
整条链路未在运行中的服务上实测。
