OpenMAIC 回放动作与多智能体编排

发表于2026-11-12|更新于2026-11-12|AI辅助开发智能体应用
|浏览量:
项目/OpenMAIC/核心知识
OpenMAIC接口与协议进阶

结论：Stage 是静态文档，「课堂能动起来」靠的是 Action 序列 + 回放引擎；多智能体（Pi 导演）
是叠加在回放之上的另一条运行时，两者通过 discussion 动作与工具调用交汇。
这一层在全仓几乎没有成文文档，只能从 packages/@openmaic/dsl/src/action.ts、
lib/playback/、lib/chat/pi/ 读出来。

1. Action：21 类，三种时序语义

action.ts:235-256 的 Action union 恰好 21 个成员，分成三族：

族 成员 语义
视觉特效 spotlight、laser FIRE_AND_FORGET：立即触发、不阻塞下一动作；且 SLIDE_ONLY（需要 slide canvas 元素）
白板 wb_open、wb_draw_{text,shape,chart,latex,table,line,code}、wb_edit_code、wb_clear、wb_delete、wb_close SYNC，必须完成后才跑下一动作
内容与控件 speech、play_video、discussion、widget_{highlight,setState,annotation,reveal} SYNC

SYNC_ACTIONS 列出 19 个（除 spotlight/laser 之外全部）。ACTION_TYPES 用
as const satisfies readonly ActionType[] 加编译期穷尽性检查（:314-320）：
新增 Action 类型却忘了加进列表，会直接编译失败，而不是让 validator 静默拒绝。
validate.ts 的 ACTION_REQUIRED_FIELDS 按类型声明必填字段，isActionType() 是零依赖的运行时窄化函数。

实操含义：调度/导出/渲染里判断「这个动作要不要等」，不要自己维护名单，直接 import
SYNC_ACTIONS / FIRE_AND_FORGET_ACTIONS / SLIDE_ONLY_ACTIONS。

2. 回放引擎（lib/playback/）

8 个文件：engine.ts、cursor.ts、types.ts、derived-state.ts、action-navigation.ts、
action-resume.ts、auto-resume.ts、index.ts。

  • 状态机：EngineMode = 'idle' | 'playing' | 'paused' | 'live'（types.ts:18）。
    **有 paused**，旧笔记里的 idle→playing→live 三段式不完整。
  • 游标：PlaybackSnapshot { sceneIndex, actionIndex, consumedDiscussions[], sceneId? }，
    通过 onProgress 回调持久化——这就是「课程能接着上次继续播」的数据基础。
  • 回调面（PlaybackEngineCallbacks）：beforeSpeech（旁白前先通知帧媒体、不等回包）、
    onEffectFire（spotlight/laser）、onSpeechStart/End、onTextDelta、onSpeakerChange、
    讨论生命周期（onProactiveShow/Hide、onDiscussionConfirmed/End、onUserInterrupt）、
    Topic/Transcript、getPlaybackSpeed、isAgentSelected（跳过未选中智能体的 discussion 动作）、onComplete。
  • TriggerEvent 驱动主动讨论卡片；TopicState = 'active' | 'pending' | 'closed'。
  • action-resume.ts / auto-resume.ts：断点续播，配合 [[04-data-model-and-three-tier-storage]] 的 runtime 记录。

3. 多智能体 / Pi 导演（lib/chat/pi/）

文件 职责
director-loop.ts、director-compaction.ts 导演循环与上下文压缩
child-runtime.ts 子智能体运行时
config.ts、prompts.ts、send.ts、tool-schemas.ts、types.ts 配置、提示词、发送、工具 schema
tools/call-agent.ts 调用某个 AI 同学/教师
tools/classroom-actions.ts、native-spotlight.ts、native-whiteboard.ts 把 LLM 决策落到课堂动作
tools/web-search.ts、read-scene.ts、cue-user.ts、close-session.ts 检索、读场景、提示用户、关会话
whiteboard-visibility.ts、element-reference.ts、interactive-state-evidence.ts 可见性 / 元素引用 / 交互状态取证

相关 API：/api/chat/pi、/api/chat/pi/whiteboard-visibility、/api/agent/{runtime,sessions,skills,owner-events,...}、
/api/agents/**（owner 隔离的智能体 CRUD）、/api/pbl/v2/** 与 /api/pbl/v3/**。

与回放的交汇点：discussion Action 会触发多智能体讨论；isAgentSelected 决定跳过哪些讨论；
live 模式下用户打断（onUserInterrupt）进入实时互动。智能体名单即 roster，
由生成管线的 agents 步骤产出（[[03-classroom-pipeline-and-async-task-contract]]）。

4. PBL 三个版本：一张导航图

版本 代码 文档
v1 / pbl dsl/src/pbl.ts 无专题
v2 / projectV2 lib/pbl/v2/、app/api/pbl/v2/{evaluate,instructor,open-task,simulator,task/update}、lib/pbl/v2/prompts/ 7 份 examples/pbl/、eval/pbl-v2-planner/
v3 / projectV3 lib/pbl/v3/、lib/server/pbl-v3/、app/api/pbl/v3/**（workspace / packages / report / terminal / events） lib/pbl/v3/ 9 篇 + lib/server/pbl-v3/ 4 篇

现有约 20 篇 PBL 专题都是分版本细节，缺一份「三版差异与选型」总览，已登记到
缺口清单。

5. 交互 Widget

dsl/src/interactive.ts 定义 InteractiveContent / WidgetConfigBase；
components/scene-renderers/ 负责渲染；public/vendor/interactive/ 是三方库；
单文件 HTML 导出时由 lib/export/standalone-html/assemble.ts 做内联（data URI 降级）。
widget_* 四个动作（highlight/setState/annotation/reveal）就是驱动这些控件的指令。

来源与可信度

packages/@openmaic/dsl/src/action.ts:230-325、lib/playback/types.ts:1-67 已抽查原文，
lib/chat/pi/、lib/playback/ 文件清单已核。本页不含运行时验证：
导演循环的具体触发条件、roster 生成策略、PBL 三版差异未逐条读源码确认，
引用具体行为前请回到 director-loop.ts / lib/pbl/v3/README.md 复核，并同步更新本页 status。
